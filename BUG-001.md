# BUG-001: Block command allows Ready→Blocked in error message but transition table disagrees

## Goal

Fix the inconsistency between `cmdBlock`'s allowed-transition list and the central `TRANSITIONS` table so that `Ready` → `Blocked` is either actually allowed or the error message is corrected.

## Background

The `block.ts` command has this logic:

```typescript
const transitionError = validateTransition(task.status, "Blocked");
if (transitionError) {
    const allowed = ["Ready", "In Progress"];
    throw new InvalidStatusTransitionError(task.status, "Blocked", allowed);
}
```

However, the central transition table in `status-transition.ts` only allows `"In Progress" → "Blocked"`, not `"Ready" → "Blocked"`. This means:

- `taskforge block TASK-001 "reason"` on a `Ready` task will throw an error saying "Allowed: Ready, In Progress" — which is misleading because `Ready` → `Blocked` doesn't actually work.
- The block command's intent (allow blocking from Ready) and the actual transition rules are out of sync.

## Scope

Allowed files/directories:
- src/commands/block.ts (fix the allowed list to match the transition table, or add Ready→Blocked to the transition table)
- src/core/status-transition.ts (if we decide to add Ready→Blocked)
- tests/

Disallowed files/directories:
- .git/**
- package.json

## Acceptance Criteria

- [ ] Tests updated to match the fix
